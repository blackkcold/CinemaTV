## Changes

- TV browsing moves to a local React/CSS frontend with cinematic artwork, floating
  glass navigation, layered highlights, clear remote focus and reduced-motion support.
- Home/discovery, movies/series, search, details/episodes, library, live guide and
  presentation settings share the new design. Existing native configuration and
  advanced tools remain reachable.
- Native Kotlin continues to own sources, account sessions, Room data and navigation;
  Media3 remains responsible for playback, decoding, tracks and subtitles.
- The bounded local-origin message bridge exposes explicit application actions and
  opaque media identifiers. Development mock content is excluded from the APK.
- Unsupported/failed WebView environments use the existing native TV presentation.
  Android8/API26 installation support and the native phone UI are retained.
- The native Web host reuses the existing Latin Noto font assets. Web CJK text uses
  the device's locale-aware system fallback; native Compose retains its packaged
  regional CJK collection. No second font binary set is added to the Web bundle.

## Dev audit fixes and completed features

- Isolate each server connection and authentication revision. Delayed status,
  login and HTTP 401 responses cannot overwrite a newer server or session; search
  authentication expiry exposes login while preserving the query and local results.
- Match LibreTV cached detail/search responses by the requested source URL before
  local keys. Same-source cache reuse across clients works; a different source URL
  remains rejected. Official 2.21.1 and 2.21.2 contracts cover this behavior.
- Preserve remote loading, retry and refresh controls even when the current
  filters match no loaded items; keep D-pad focus stable while loading.
- Retain live channel variants that share an EPG ID through source/channel/URL
  identity. Refresh visible guide time and filter expired entries before bounding
  the native presentation window.
- Distinguish resume from restart. Completed episodes start from zero when selected
  again; unfinished episodes offer both actions without deleting their checkpoints.
- Route native connection, source, update, developer, recommendation and library
  tools to their actual destinations. Review retained legacy progress and its
  original source without silently attaching or deleting uncertain checkpoints.
- Discover SourceList subscriptions advertised by LibreTV; preview, import and
  refresh normalized VOD/live lists with skipped-item reasons, persistent ownership
  and change summaries. Refresh failures preserve existing data, disabled choices,
  manual sources and unrelated subscriptions. Unchanged refresh keeps source
  precedence; stopping a subscription retains only its currently effective sources
  as manual entries. TVBOX direct entries use upstream parsing;
  no Spider execution engine is added.
- Share one foreground-aware Media3 system session across TV and phone players.
  Handle media audio focus, output-disconnection pause and media controls; preserve
  user pause through background transitions and asynchronous link replacement.
- Restore hybrid live groups, rating-provider filters and recommendation reasons.
- Reject optional BFF authentication redirects, including 307/308 requests that
  would otherwise forward the configured password; share concurrent authentication
  and reject a stale failure that could clear a renewed session.

## Evidence and publication state

The hybrid workflows produce exact-source browser evidence, Android debug test
APKs, a public **unsigned** Dev candidate, actual Android TV API26/API29/API36
receipts (1080p and 4K), and independent API35 phone regressions. API29 uses the
installed provider's documented capability decision rather than forcing an old
WebView into hybrid mode. The official compatibility matrix executes checksum-pinned,
unmodified LibreTV 2.21.1 and 2.21.2 with controlled fixtures.
Their definitions do not establish that the jobs passed. Record the successful
exact-head run URLs and the final signed artifact's acceptance before publication.

Signing changes the APK bytes. The source/unsigned receipt cannot substitute for the
final signed SHA-256, certificate verification or installation/upgrade evidence.
No CI workflow receives the production key. See [hybrid build and handoff](../HYBRID_TV.md).

Synthetic browser/emulator evidence does not establish physical TV performance,
low-memory budgets, HDR/codec breadth, four-hour playback or the final live update
download/installer flow. Report these limits with the final release; never present
an unsigned candidate or debug APK as an accepted same-signature Dev upgrade.
