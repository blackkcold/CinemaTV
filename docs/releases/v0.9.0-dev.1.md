# CinemaTV 0.9.0-dev.1 · Hybrid TV

**Reserved Dev version: 0.9.0-dev.1 / code13. This document is not a publication or
signed-artifact acceptance receipt.**

## Changes

- TV browsing moves to a local React/CSS frontend with cinematic artwork, floating
  glass navigation, layered highlights, clear remote focus and reduced-motion support.
- Home/discovery, movies/series, search, details/episodes, library, live guide and
  presentation settings share the new design. Existing native configuration and
  advanced tools remain reachable.
- Native Kotlin continues to own sources, account sessions, Room data and navigation;
  Media3 remains responsible for playback, decoding, tracks and subtitles.
- The bounded local-origin message bridge exposes explicit application actions and
  opaque media identifiers. Development mock content is excluded from the APK.
- Unsupported/failed WebView environments use the existing native TV presentation.
  Android8/API26 installation support and the native phone UI are retained.
- The native Web host reuses the existing Latin Noto font assets. Web CJK text uses
  the device's locale-aware system fallback; native Compose retains its packaged
  regional CJK collection. No second font binary set is added to the Web bundle.

## Evidence and publication state

The hybrid workflows produce exact-source browser evidence, Android debug test
APKs, a public **unsigned** Dev candidate and Android TV API36/API26 device receipts.
Their definitions do not establish that the jobs passed. Record the successful
exact-head run URLs and the final signed artifact's acceptance before publication.

Signing changes the APK bytes. The source/unsigned receipt cannot substitute for the
final signed SHA-256, certificate verification or installation/upgrade evidence.
No CI workflow receives the production key. See [hybrid build and handoff](../HYBRID_TV.md).

Synthetic browser/emulator evidence does not establish physical TV performance,
low-memory budgets, HDR/codec breadth, four-hour playback or the final live update
download/installer flow. Report these limits with the final release; never present
an unsigned candidate or debug APK as an accepted same-signature Dev upgrade.
