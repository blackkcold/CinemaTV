# CinemaTV v0.7.0-preview · Inspectable Local Recommendations

Android phone/TV debug-signed preview. This adds the actual RankSys recommendation integration and dashboard beyond v0.6; it is not stable signing, physical-device certification or a personal Douban account connection.

## New since v0.6

- The production local ranker now invokes original published RankSys 0.4.3 cosine and greedy average-distance MMR classes. A separate, versioned CinemaTV adapter makes singleton/zero-variance normalization finite and records the actual decisions. This is neither a trained model nor an unchanged stock-library behavior claim.
- Settings opens a phone/TV recommendation dashboard showing the real engine/version, manual signal weights, normalized sparse preference tags, exclusions, viewing tiers and actual per-step relevance/diversity contributions. The home shelf and explanations use the same immutable snapshot. TV focus survives refresh, Back and reopen.
- Existing local favorites, want-to-watch, watching, watched, dropped/negative feedback and progress feed the ranking. These marks were already in v0.6; this release reuses them rather than creating another store. No Room schema migration or history replacement is introduced.
- Duplicate-work evidence is conservatively grouped and capped. Negative feedback excludes a work. Unseen, in-progress and watched works rank in separate tiers. Missing metadata is labeled; cold start retains provider order. A failed backend discards partial output and visibly falls back. Work is bounded and cancellable off the UI thread.
- Complete MPL-2.0/Apache-2.0/version-specific notices and the exact three SHA-pinned RankSys source archives are embedded. The dashboard can export only six fixed public source/license assets using Android's file picker. No preferences, titles, playback URLs or account data enter that ZIP. TVs without a document picker can extract the same assets from the APK.

## Verification and release gate

The module's exact pre-release code passed 254 Android-build JUnit cases, Lint, APK signature/archive checks, 37 focused JVM tests with the five real runtime JARs, and focused phone/API33, TV/API33 and TV/API26 dashboard tests. The isolated actual-core experiment passed ten tests per API26/API33 plus R8-minified startup and matching-source/license checks. These are module evidence, not a substitute for this release's final gate.

Publication requires the versioned candidate's full phone/API30, TV1080/API33, TV4K/API33 and compatibility/API26 matrix, including the appropriate recommendation dashboard class and existing library/playback/font/glass tests. The original official LibreTV protocol/playback acceptance remains unchanged. The linked release run and same-tree promotion receipt identify the exact tested checkout and APK; only that APK may be published. API26 dashboard evidence uses the real Dialog window via PixelCopy, not physical display readback. See [promotion verification](../PREVIEW_PROMOTION.md).

## Privacy, resources and limits

- Profiles and ranking remain on-device. Other CinemaTV network features still contact configured services; the whole app is not claimed to be offline.
- No embeddings, external model dataset, collaborative user database or machine-learning training is shipped. Manually chosen weights are not learned coefficients, and scores are not calibrated liking probabilities or quality ratings. NewsBar informed the explicit-feedback/explainability approach, not an imported trained model.
- The five original runtime JARs introduce no JNI, account or ranking network service. The pre-release integration debug APK was 5.863 MiB larger than its exact baseline; this is a measured APK comparison, not isolated heap or hardware latency. Production shrinking was not changed. Physical low-memory-device and long-session performance remain open.
- Personal Douban watched/want-to-watch/rating sync is not connected. A future importer must preserve source/timestamps, preview identity matches, confirm merges, deduplicate and support undo. No cookies or account credentials were accessed.
- v0.6's official playback evidence does not establish every codec, HDR, full-film decode, home-server compatibility or four-hour soak. Those stable-release limits and private production signing remain open.
- CI debug signing keys can differ between releases. Do not uninstall an existing app merely to resolve a signature mismatch: uninstall deletes local favorites/history. Preserve existing data and review [installation](../INSTALL.md) before replacement.
