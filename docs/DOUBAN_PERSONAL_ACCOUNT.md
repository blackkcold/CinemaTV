# 豆瓣个人账号接入（开发中）

## 当前验证边界

此功能与面向公共目录的 BFF Top250 采集独立。仅用于用户手动连接自己的账号和片单，不提供账号共享、公共抓取代理或规避验证的路径。

2026-11-05 已通过官方扫码在独立浏览器确认登录和个人动态可见；个人主页导航未完成。**尚未证明 Android WebView 登录、个人完整片单分页、真实评分详情请求或 App 会话保存成功。** 代码内片单 DOM 合约仍需要获准的正常账号验证，合成测试不代替该验收。

## App 流程

1. 设置 → 豆瓣个人账号与片单 → 官方扫码登录。
2. 独立原生 Activity 展示豆瓣官方 HTTPS 登录页。页面的 QR 由豆瓣生成，使用豆瓣 App 扫描；CinemaTV 不生成私有登录协议、不代理手机登录、不提供密码/Cookie 粘贴框。
3. 用户完成官方登录后，点击「已完成登录，验证并保存」。原生确认说明本机持续访问用途和会话风险。
4. 用户明确允许后，App 在设备内取得 movie.douban.com 的 Cookie，访问固定官方账户页核对账号，再用 Android Keystore AES-GCM 存储。没有向开发者、云端、BFF 或 LAN 浏览器迁移会话。
5. 每次手动同步最多20页，请求至少间隔4秒。继续同步是另一次用户动作。401/403/418、官方安全验证跳转和200验证页停止；429保留服务器Retry-After。取消和出错保留原快照，不伪报空片单或完成。
6. 本机会话七天后要求重新验证；可断开并删除。删除连接保留已导入片库；不会注销其他设备。

官方页面浏览过程由系统 WebView 临时持有 Cookie。Activity 正常关闭时清除 WebView Cookie、缓存和 WebStorage；App 重新启动时及断开账号时再次清理。Android 进程异常终止不保证调用 onDestroy，系统 WebView 仍可能在下次启动清理前留下临时 Cookie。App 自己保存的会话位于 noBackupFilesDir 加密文件。系统 WebView/OS 自身临时存储不等于全程无明文，不能宣称防 root 或硬件级设备攻破。应用禁止该 Activity 截图，系统备份/迁移已排除 App 数据。

## LAN 参考与边界

参考 [aerial-tv PhoneServer 架构](https://github.com/pengchujin/aerial-tv/blob/main/docs/ARCHITECTURE.md) 的“TV 拉起设置页，手机扫码操作”交互，独立实现。没有复制实现源码。

- App 用户显式打开后，绑定一个私有 IPv4 地址和临时端口。
- 192-bit随机路径令牌、10分钟到期、严格Host/Origin和请求头校验。
- 仅允许请求 TV 打开官方登录页，真正登录/保存确认仍在 TV。
- LAN 不接收或返回 Cookie、密码、账号ID或个人片单；无第三方资源和遥测。
- HTTP 在可信局域网仅作为非秘密的遥控入口；不是安全会话传输通道。退出面板立即停止服务。

## 数据语义

- 看过collect、想看wish、在看do分别保留；个人星级1–5不当作社区评分0–10。
- 本地导入仅按明确豆瓣作品ID匹配，禁止仅按片名合并。数据库事务内重新检查冲突，保留本机观看状态、收藏和播放进度；不回写豆瓣。
- 没有上映年份/影视类型证据时保持未知，不推断电影或剧集。
- 社区评分需用户单独点击，每轮最多读取自己片单内10部作品，使用相同请求间隔和访问限制停止逻辑。无评分保持未知，不将个人数据写成有目录授权的公共评分或TOP250。
- 会话、真实页面、账号数据和截图不得写入仓库、CI日志或CI附件。
