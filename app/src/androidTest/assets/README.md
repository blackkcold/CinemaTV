# Original playback fixture

`playback-fixture.mp4` contains a solid blue H.264 picture and a synthesized
220 Hz AAC tone, 320×180 at 12 fps, 30 seconds. It is generated by this project
and may be redistributed under the repository MIT license. It is bundled only
in the instrumentation APK, never as a stream in the user app.

## Pinned provenance

- Original asset first committed in `577bd94` by this project, using the two
  FFmpeg `lavfi` sources in `scripts/generate-test-media.sh`. No downloaded
  video, production stream or third-party movie is used.
- File size: **110,238 bytes**.
- SHA-256: `952ce514387abebceaca2a9071559f1242caefbfd421ba3cdd5c18ac36187d21`.
- Verified streams: 30-second H.264 High / yuv420p video, 320×180, 12 fps,
  360 frames; 30-second AAC-LC mono audio at 44,100 Hz.
- Embedded encoder metadata: `Lavf60.16.100`, `Lavc60.31.102 libx264`.
  These describe the existing bytes, not the locally installed FFmpeg version.

`bash scripts/generate-test-media.sh` validates these exact committed bytes with
`sha256sum` (or `shasum` on developer machines). It fails on missing or changed
bytes and never downloads or regenerates them implicitly. Both standalone device
QA and the APK workflow use this offline path. A clean checkout contains everything
needed for this fixture; there is no dependency on another workflow's artifacts
or on FFmpeg being installed. Other build dependencies are separate.

## Deliberate regeneration

`bash scripts/generate-test-media.sh --regenerate` requires FFmpeg with `libx264`
and AAC support. It recreates the same original color/tone sources and encoding
parameters, without replacing the current file if encoding fails. Different
FFmpeg versions may produce different bytes. The script does **not** change the
pinned checksum automatically: if regenerated bytes differ, it retains the new
file for review and exits nonzero until that review updates the pin.

Before accepting changed bytes, inspect their metadata and fully decode them:

```sh
ffprobe -v error -show_format -show_streams -of json app/src/androidTest/assets/playback-fixture.mp4
ffmpeg -v error -i app/src/androidTest/assets/playback-fixture.mp4 -map 0:v:0 -map 0:a:0 -f null -
sha256sum app/src/androidTest/assets/playback-fixture.mp4
```

Confirm the same synthetic source, streams, duration, resolution, frame rate and tone.
Update `expected_sha256` in the script, the file size/encoder metadata/checksum
above, and the asset together in a reviewed change. Rerun the host tests and
device playback acceptance for that change. To discard regeneration, restore the
fixture from Git. Synthetic playback evidence does not establish public-source,
production-content, format-breadth or physical-device acceptance.
